# Polixor

**ניתוח שידורים ויצירת קליפים ו‑Shorts אוטומטית**

Polixor מקבל קישור לשידור של סטרימר (או קובץ וידאו מהמחשב), מנתח אותו,
מאתר את הרגעים המעניינים וחותך מהם אוטומטית קליפים ארוכים ל‑YouTube
וסרטונים אנכיים ל‑Shorts/TikTok — עם כתוביות בעברית ובאנגלית, מוכנים
לצפייה, לעריכה ולהורדה. הממשק זמין בעברית ובאנגלית.

התוכנה רצה **מקומית במחשב שלך**. הווידאו, התמלול והקליפים נשארים אצלך.

> **רוצים לנסות את התוכנה?** ההוראות המלאות – הפעלה ב‑Windows/Mac/Linux,
> פתיחה מהאייפון, פרויקט ראשון, מפתחות API וייצוא – נמצאות ב‑
> [TESTING_GUIDE.md](TESTING_GUIDE.md) (באנגלית). בקצרה: לחיצה כפולה על
> `Polixor.bat` (או `Polixor-Phone.bat` לגישה מהטלפון), או `bash scripts/run.sh`.
>
> **בלי התקנה:** פתחו את הקישור הזה ולחצו *Create codespace* – Polixor
> יותקן ויעלה בענן בחשבון ה‑GitHub שלכם, בכתובת HTTPS מוגנת בסיסמה
> שנפתחת גם מהאייפון: https://github.com/codespaces/new?hide_repo_select=true&ref=claude%2Fproject-build-requirements-nragi5&repo=1375783025&machine=standardLinux32gb

## שדרוג 2.0 — פרויקטים, שתי שפות ועריכה מקצועית

השדרוג הופך את Polixor ממסך „משימה אחת עם הגדרות גלובליות" למסלול
עבודה של **פרויקט**: ייבוא → ניתוח → בחירת מצב → הגדרות → יצירה →
תוצאות. כל פרויקט נשמר, אפשר לחזור אליו, לשנות הגדרות וליצור שוב
**בלי לנתח מחדש**.

### מה נוסף

| תחום | מה קיים עכשיו |
|---|---|
| **זרימת פרויקט** | מסך „פרויקט חדש" (`/new`) ומסך פרויקט (`/projects/:id`) עם Stepper. הניתוח נשמר (`analysis_store`), ההגדרות נשמרות אוטומטית, ו„יצירה מחדש" משתמשת בניתוח הקיים. משימות ישנות מוצגות כפרויקטים, והמסך הישן זמין ב‑`/legacy/jobs/:id`. |
| **ייבוא מקישור** | YouTube (כולל Shorts ו‑Live), Twitch (VOD, קליפ, ערוץ חי, כולל `?t=`), Kick, Google Drive וקישור ישיר. בדיקת קישור לפני ייבוא, בחירת טווח (חובה כשהסרטון ארוך מהמגבלה בהגדרות, ברירת מחדל 12 שעות), הקלטה משידור חי למשך שנבחר, והגנת SSRF. הורדה שבוטלה או נכשלה לא משאירה קובצי `.part`. |
| **facecam / Reaction** | זיהוי אזור המצלמה בפינת הפריים (`layout_detect`) ופריסת שני פאנלים — תוכן ומצלמה — בלי לחתוך פנים. הפריסה „אוטומטי" בוחרת לכל קטע: תגובה, מעקב פנים או חיתוך מרכזי, ומסבירה את הבחירה. |
| **Short Clips** | מספר קליפים, טווח אורך, יחס מסך (9:16, 1:1, 4:5, 16:9) ופריסה לכל פרויקט. |
| **Long‑Form** | אלגוריתם נפרד (`longform.py`): חלוקה לנושאים (TextTiling), הסרת אוויר מת, AFK, מילוי, חזרות ושיחה שלא בנושא, תקציב לכל נושא, פתיח לכל קטע, קיצור שתיקות, ופרקי YouTube מתוך הדיבור. תוצר אחד ב‑16:9 עם קובץ פרקים והסבר מלא מה הוסר ולמה. |
| **שתי שפות** | כל הממשק בעברית ובאנגלית (i18next), כולל RTL/LTR מלא, מספרים ותאריכים לפי שפה, ושפה שנבחרת אוטומטית – אין בורר שפה: כותרת מדינה מ-CDN/פרוקסי מהימן (ישראל → עברית RTL) ← אזור זמן ישראל או דפדפן בעברית ← אנגלית LTR. בלי GPS ובלי שמירת מיקום; בחירה ידנית ישנה נמחקת. לבדיקות ותמיכה בלבד: `?lang=he` / `?lang=en` בכתובת (ללשונית הנוכחית; `?lang=auto` מבטל). כותרות המדינה: `POLIXOR_COUNTRY_HEADERS` (או `none`). השרת מחזיר כל הודעה, שגיאה, הסבר והערה בשפת הבקשה (או בשפת הפרויקט בעיבוד ברקע) מקטלוג אחד (`polixor/locales`). |
| **כתוביות v2** | מעצב כתוביות עם תצוגה מקדימה אמיתית (מרונדרת ב‑libass כמו הייצוא, 85–140ms), חמישה פריסטים, גופן ומשקל עם זיהוי כיסוי עברית, רקע תיבה/פס, מתאר, צל, מיקום, אזור בטוח ואנימציות. השבירה לשורות מבוססת **מדידת רוחב אמיתית** של הגופן, מאוזנת, בלי מילת קישור תלויה בסוף שורה, וסדר מילים RTL נכון גם עם מספרים ופיסוק. |
| **ממשק חדש** | מערכת עיצוב אחת (`components/ds`), ערכת צבעים בהירה/כהה, רספונסיבי עד 390px בלי גלילה אופקית, ונגיש (תוויות, role, מקלדת). |

### איך לבדוק ידנית

1. **שפה:** בסרגל העליון בחרו English — כל המסכים מתהפכים ל‑LTR. רעננו: הבחירה נשמרת. הגדרות → כללי מציג את אותו בורר ואת ערכת הצבעים.
2. **ייבוא קובץ:** פרויקט חדש → קובץ מהמחשב → גררו MP4 → „ייבוא וניתוח". פס ההתקדמות אמיתי, ואפשר לבטל.
3. **ייבוא מקישור:** פרויקט חדש → קישור → הדביקו YouTube/Twitch/Kick → „בדיקה". מופיעים פלטפורמה, אורך ותמונה. בסרטון ארוך סמנו „לייבא רק חלק" ובחרו טווח. בערוץ Twitch/Kick חי מופיע „משך ההקלטה".
4. **ניתוח:** במסך הפרויקט מופיע סיכום הניתוח: משך, שפה, תמלול, רגעים, אודיו, פנים, facecam ודוברים.
5. **Shorts:** בחרו Short Clips, יחס 9:16, פריסה „אוטומטי", ופריסט כתוביות. התצוגה המקדימה משתנה עם כל שינוי. „יצירה" → הקליפים מופיעים בתוצאות.
6. **Reaction:** על סרטון עם מצלמה בפינה, פריסה „תגובה" מציגה תוכן ומצלמה יחד.
7. **Long‑Form:** בחרו Long‑Form ואורך יעד. בתוצאה מופיעים פרקים, מה הוסר ולמה, וכפתור העתקת פרקי YouTube.
8. **עריכת קליפ:** שנו טווח, יחס מסך או סגנון כתוביות → „ייצוא מחדש". הכתוביות נשארות מסונכרנות.
9. **שמירה:** סגרו את הדפדפן, פתחו שוב — הפרויקט, ההגדרות והתוצאות במקומם. „שינוי הגדרות" → „יצירה מחדש" לא מנתח שוב.

## התקנה ב‑Windows

### הדרך הפשוטה — לחיצה כפולה

1. לחץ ימני על `polixor.zip` ← **חלץ הכול**.
2. בתיקייה שנוצרה, לחץ פעמיים על **`Polixor.bat`**.
3. בפעם הראשונה הוא מתקין את מה שחסר (כמה דקות, פעם אחת). אם Windows
   שואל על הרשאה להתקין Python או FFmpeg — אשר.
4. הדפדפן נפתח לבד כשהשרת מוכן, בכתובת `http://127.0.0.1:8756`.

מהפעם השנייה והלאה — אותה לחיצה כפולה, והאתר עולה תוך שניות.

**לא צריך Node.js.** הממשק מגיע כבר בנוי בתוך החבילה.

> **אם לחצת על `Polixor.bat` מתוך ה‑ZIP בלי לחלץ** — Windows מריץ אותו
> לבד מתיקייה זמנית, בלי שאר הקבצים. הקובץ מזהה את זה ומסביר מה לעשות.

#### מה ההתקנה עושה

- מחפשת Python 3.10+ (`py` לפני `python` — ב‑Windows נקי, `python`
  הוא לרוב קיצור של חנות Microsoft שלא מריץ כלום), ומתקינה 3.12 דרך
  winget אם חסר. אחרי ההתקנה היא ממשיכה — לא צריך להריץ שוב.
- מחפשת FFmpeg ומתקינה אם חסר, **ובודקת שוב** שהוא באמת זמין.
- יוצרת סביבה וירטואלית ב‑`.venv` ומתקינה את חבילות ה‑Python.
- מריצה בדיקת תקינות ומדפיסה מה קיים ומה חסר.

אם שלב נכשל, ההתקנה עוצרת עם הסבר — ולא ממשיכה להפעיל שרת שבור.
סביבה שהתקנתה נכשלה באמצע נמחקת, כך שהלחיצה הבאה מנסה מחדש.

הודעות חלון ההתקנה הן באנגלית: קונסולת Windows אינה תומכת בכיווניות
עברית ומציגה אותה הפוכה. האתר עצמו כולו בעברית.

### למה לא רק צעקות

חלק מהרגעים הכי טובים בשידור **שקטים**: סיפור אישי, גילוי, נקודה חדה
בוויכוח. מערכת שמחפשת רק פרצי עוצמה תפספס אותם.

לכן הציון הסופי אינו ממוצע פשוט:

```python
score = 0.60 × (סכום משוקלל של כל הערוצים)
      + 0.40 × (הערוץ החזק ביותר)
```

החלק השני הוא המפתח: רגע שקט עם ציון לשוני גבוה (`תקשיבו, אספר לכם
משהו שלא סיפרתי לאף אחד`) מקבל ציון גבוה גם כשערוץ העוצמה אפסי.
יש לזה בדיקה אוטומטית ייעודית — `test_quiet_moment_is_findable`.

בנוסף, ערוץ `pause` מזהה שתיקה של 0.8–6 שניות שאחריה דיבור, ומחזק את
החלון שאחריה — התבנית של "רגע, תקשיבו…".

### קליפים ארוכים עם התחלה, אמצע וסוף

הבחירה של קליפ ארוך לא מסתפקת בממוצע ציון גבוה. לכל חלון מועמד מחושב
**ציון קשת** (`_arc_quality`) שבודק:

| מרכיב | מה נמדד |
|---|---|
| מיקום השיא | רצוי בשליש האמצעי‑מאוחר (סביב 55% מהקטע) |
| בנייה | האמצע חזק מההתחלה |
| סגירה | ירידה בסוף, אבל לא קריסה |
| שונות | קטע שטוח אינו סיפור |

`total = ממוצע_ציון × (0.65 + 0.35 × ציון_קשת)` — כך חלון עם סיפור
מנצח חלון שטוח עם אותו ממוצע.

## מנוע העריכה

זה ההבדל בין קטע שנחתך מהשידור לבין קטע שמרגיש ערוך.

במקום לחתוך טווח רציף אחד, המנוע בונה **רשימת החלטות עריכה** (EDL):
סדרת "ביטים", לכל אחד זמני מקור, גודל פריים ומהירות משלו. הרינדור
מבצע את כל הרשימה ב‑`filter_complex` אחד, עם `-ss` מהיר בכניסה — כך
שגם שידור של שלוש שעות לא מפוענח כדי להגיע לדקה 90.

### מה המנוע עושה

| החלטה | למה |
|---|---|
| **הסרת אוויר מת** | שתיקות בין משפטים הן מה שהכי מסגיר "וידאו גולמי". המנוע מאתר אותן מהרווחים בין מילים בתמלול (או ממסכת השקט כשאין תמלול) ומסיר אותן. |
| **הגנה על שתיקה דרמטית** | אבל לא כל שתיקה היא אוויר מת. "רגע… תקשיבו" צריך את השקט שלו. שתיקה שערוץ ה‑pause סימן כמשמעותית **מקוצרת** ל‑0.4–0.55 שניות במקום להימחק. |
| **הידוק ראש וזנב** | הקליפ מתחיל על המילה הראשונה ונגמר על האחרונה, לא על שנייה וחצי של כלום. |
| **שינוי זווית בחיתוך** | שינוי קל בגודל הפריים בדיוק בנקודת החיתוך נקרא כמעבר בין שתי מצלמות. זה מה שהופך jump cut למכוון. |
| **דחיפה מדורגת על השיא** | ביט השיא מתפצל לשלושה תת‑ביטים עם זום עולה (1.13× → 1.16× → 1.18×). |
| **האצת קטעים מתים** | ב‑`hype`, קטע ארוך בלי דיבור מואץ ×1.35 במקום להיחתך לגמרי. |
| **ניקוי נקישות** | כל חיתוך אודיו בלי fade מייצר נקישה. 20 מילישניות בכל תפר פותרות את זה, מתחת לסף השמיעה. |
| **ליטוש אודיו** | highpass 65Hz, איזון עוצמות, דחיסה קלה ולימיטר בסוף כדי שהפלט לא ייחתך. |

### ארבעת הסגנונות

| סגנון | מה הוא עושה | טיפוסי |
|---|---|---|
| **גולמי** | חיתוך ישיר, ללא שום התערבות. שימושי להשוואה. | — |
| **נקי** | הסרת אוויר מת + הידוק ראש/זנב + ליטוש אודיו. נאמן למקור. | ~22% קוצר |
| **דינמי** | בנוסף: שינויי זווית, דחיפה על השיא, צבע מוגבר. ברירת המחדל לשורטים. | ~22% קוצר, 4–6 זוויות |
| **אנרגטי** | הכי הדוק: הסרה אגרסיבית, יותר זוויות, האצה, כתוביות קופצות. | ~24% קוצר, 5–8 זוויות |

הסגנון נקבע בנפרד לקליפים ארוכים ולשורטים, וניתן להחליף אותו לכל
קליפ בנפרד במסך העריכה ולייצא מחדש.

### גבולות שהמנוע לא חוצה

- **תקרת הסרה** (`max_removed_ratio`): 25%–42% מאורך הקליפ לפי הסגנון.
  אפשר להסיר כל שתיקה ולקבל משהו שנשמע כמו מקלע; המכסה מונעת את זה.
- **תקרת זום** (`MAX_ZOOM = 1.18`): חיתוך אנכי כבר מגדיל פי 1.78,
  וזום נוסף מצטבר. מעל 1.18 התמונה מתרככת בצורה מורגשת.
- **תקרת ביטים** (`MAX_BEATS = 36`): מעבר לזה גרף הפילטרים נעשה כבד
  והקליפ קופצני.
- **האצה רק בלי דיבור**: ביט מואץ רק אם פחות מ‑12% ממנו הוא דיבור.

### סנכרון הכתוביות

כשהעורך מסיר אוויר מת, כל מה שאחרי החיתוך זז אחורה. אם הכתוביות לא
זזות איתו הן מתנתקות מהדיבור — וזה הבאג הכי קל להחמיץ במערכת כזו.

לכן כל כתובית עוברת מיפוי דרך `EditPlan.map_span()`:

- כתובית שנחתכה כולה — נעלמת
- כתובית שנחתכה חלקית — מתכווצת, **והטקסט שלה מתעדכן** כדי שלא יוצג
  מה שכבר לא נשמע
- תזמוני המילים בתוכה ממופים בנפרד

יש לזה בדיקה ייעודית: `test_cues_stay_in_sync_after_cuts`.

### למה לא זום רציף

הניסיון הראשון היה זום כפונקציה של הזמן. FFmpeg דחה אותו:

```
Error when evaluating the expression 'floor(640/((1.0000+(0.1000)*...)))'
```

פילטר `crop` מעריך את `w`/`h` **פעם אחת** בהגדרת הגרף, בלי גישה ל‑`t`.
הפתרון — דחיפה מדורגת — הוא גם מה שאפשרי טכנית וגם מהלך עריכה אמיתי
שעורכים עושים ממילא.

### Smart Reframe

| פריסה | מה עושה |
|---|---|
| **חיתוך מרכזי** | חיתוך סטטי מהמרכז. תמיד עובד, ללא תלות בזיהוי. |
| **מעקב אחרי פנים** | מסלול מוחלק של מרכז הפנים, עם **אזור מת** של 3.5% והגבלת מהירות תזוזה — כדי שהמסגרת לא תרעד. המסלול מקודד כביטוי קטעי‑לינארי של FFmpeg. |
| **מסך מפוצל** | מצלמת הסטרימר למעלה (38%), גיימפליי למטה (62%). אזור המצלמה מזוהה אוטומטית או מוגדר ידנית ונשמר. |
| **מסגרת מלאה על רקע מטושטש** | הפריים המלא במרכז על רקע מטושטש של עצמו. שום דבר לא נחתך, ואין הגדלה — ולכן התמונה נשארת חדה כמו במקור. |

אם לא זוהו פנים — המערכת **נופלת בחזרה לחיתוך מרכזי ומדווחת על כך**
במסך העריכה, במקום לייצר קליפ עם מסגרת קופצת.

### כתוביות בעברית

הכתוביות מיוצרות כקובץ **ASS** ונצרבות עם `libass`, שמבצע את סידור
ה‑bidi ואת עיצוב האותיות בזמן הרינדור. הטקסט נשמר בקובץ בסדר לוגי.

- **תזמון ברמת מילה** — כל מילה מודגשת בתורה (בסגנון שורטים מודרניים)
- **שבירת שורות תלוית רזולוציה** — `(רוחב − שוליים) / (גודל_גופן × 0.52)`
- **בחירת גופן אוטומטית** — אם הגופן המבוקש לא תומך בעברית, נבחרת חלופה
- **עריכה לפני ייצוא** — כל שורה ניתנת לתיקון, והטקסט המקורי מהתמלול נשמר לצידה

> **חשוב:** FFmpeg שלך חייב להיות מקומפל עם `--enable-libass`
> ו‑`--enable-libfribidi`. הבילדים של Gyan (שה‑winget מתקין) כוללים
> את שניהם. לבדיקה: `ffmpeg -version | findstr fribidi`

## במאי ה‑AI

הבמאי הוא שכבה שמבינה את הסרטון **לפני** שמתחילים לערוך אותו. הוא
לא מבצע דבר: הוא מחזיר `VideoEditPlan` — נתונים בלבד — והביצוע קורה
אחר כך, מתוך התכנית. כך אפשר להציג אותה למשתמש, לשנות אותה, ולהסביר
כל החלטה.

### מה נכנס לתכנית

| שדה | מה יש בו |
|---|---|
| `hook` | ניקוד שלוש השניות הראשונות, גיזום הקדמה, והצעה להזיז משפט חזק לפתיחה |
| `beats` | חלוקה לתפקידים: hook, setup, main_idea, tension, emotional_peak, payoff, key_claim, cta, topic_change, filler |
| `pacing` | מרווח בין שינויים ויזואליים לכל קטע, לפי התפקיד ולפי הסגנון |
| `cuts` | אוויר מת, היסוסים, מילות מילוי, התחלות כושלות, וחזרות |
| `zoom_events` | שינויי מסגור מוצדקים, בתוך תקרת זום שנגזרת מרזולוציית המקור |
| `captions` | אילו מילים להדגיש, במכסה לדקה |
| `broll` | הצעות לחומר נלווה — **תמיד** מושבתות כברירת מחדל |
| `unimplemented` | קטגוריות שאינן מתוכננות בגרסה הזו, מוצהרות במפורש |

כל החלטה נושאת `start`, `end`, `reason`, `confidence`, `priority`
ו‑`enabled`. החלטה שנשקלה ונדחתה נשארת בתכנית עם ההסבר למה — במסך
עריכת הקליפ אפשר לראות את כולן.

### תקרת זום לפי רזולוציה

חיתוך ל‑9:16 ממקור 16:9 כבר מותח את התמונה, עוד לפני שום זום. התקרה
מחושבת כך שהמתיחה **הכוללת** לא תעבור פי 2:

| מקור | מתיחת בסיס ל‑1080×1920 | זום מרבי |
|---|---|---|
| 3840×2160 | 0.89× | 1.30× (התקרה המוחלטת) |
| 1920×1080 | 1.78× | 1.12× |
| 1280×720 | 2.67× | **1.00× — אין זום כלל** |

מקור 720p שנחתך לאנכי כבר מתוח מדי; המערכת משאירה את המסגור קבוע
ורושמת בתכנית למה.

### כתוביות

חמישה פריסטים על **אותו מנוע** (נקי, ויראלי, קולנועי, פודקאסט,
סיפור). הקיבוץ מודע לפיסוק: נקודה שוברת תמיד, פסיק רק כשהכתובית
מלאה. השורות מאוזנות באורכן ואינן מסתיימות במילית קישור. השוליים
מחושבים מגובה הפריים כך שהכתובית לא תיפול מתחת לממשק של הפיד, וגודל
הגופן מוקטן יחסית לרזולוציית הייצוא.

### חומר נלווה — מתי הדובר עדיף

השאלה אינה „איזו תמונה מתאימה למשפט" אלא **האם בכלל צריך תמונה**.
תמונה לכל משפט מרחיקה את הצופה מהדובר בדיוק ברגעים שבהם הוא הכי
חשוב. לכן כל משפט מקבל הכרעה מפורשת עם נימוק:

| מצב | ההכרעה |
|---|---|
| פתיח, קריאה לפעולה | **הדובר** — פנייה ישירה; חיתוך מהפנים שובר את הקשר |
| רגע רגשי בלי תיאור חזותי | **הדובר** — הרגש נישא בהבעה ובקול |
| רגע רגשי **עם** סצנה מוחשית | חומר נלווה — הוא משרת את הרגש ולא מחליף אותו |
| דעה או רעיון מופשט | **הדובר** — תמונה תהיה גנרית ולא תוסיף מידע |
| דיבור על הסרטון עצמו | **הדובר** — אין כאן מה לצלם |
| משפט קצר מ‑1.6 שנ' | **הדובר** — הכנסה תיראה כמו הבהוב |
| תיאור מקום, אובייקט, פעולה או סביבה | חומר נלווה |

„מוחשיות" נמדדת מלקסיקון של מקומות, אובייקטים, תנועה וטבע — **בגבולות
מילה**. התאמת תת‑מחרוזת סיווגה „אני רוצה **לבד**וק את זה" כרגע רגשי
נמוך והפיקה לו תמונה חשוכה; זה תוקן בשני המנועים.

חומר שכבר קיים (הועלה או נוצר קודם) מועדף על יצירה חדשה — זול יותר,
מהיר יותר ועקבי יותר ויזואלית. ההתאמה מתעלמת מתחיליות דבוקות, כך
ש„בכביש" מוצא נכס שמתויג „כביש".

הפרומפט נבנה באנגלית ומתאר **סוג צילום**, לא תרגום מילולי. הוא כולל
תמיד `no text`, `no watermark` ו‑`no recognisable faces`.

### מוזיקת רקע

**המערכת אינה מספקת מוזיקה.** אין ספריית מוזיקה ואין הורדה מאף
מקור — אתה מביא קובץ שיש לך זכות להשתמש בו, והמנוע מערבב אותו
נכון. בלי קובץ, התכנית מוחזרת לא פעילה עם ההסבר.

**ההנמכה** נעשית בדחיסת sidechain שהקול עצמו מנהל, ולא בחיתוך לפי
זמנים — ולכן היא מגיבה לדיבור בפועל, כולל להפסקות קצרות. נמדד על
פלט אמיתי:

| פרופיל | יעד המצע | הנמכה שנמדדה |
|---|---|---|
| מינימלי | ‎-34 LUFS | 10.6 dB |
| מאוזן | ‎-29 LUFS | 11.0 dB |
| אנרגטי | ‎-25 LUFS | 11.1 dB |

**העוצמה נגזרת מהקובץ שלך.** „הנמך ב‑20dB" נותן תוצאה אחרת לכל
קובץ מוזיקה, ולכן היעד מוגדר ב‑LUFS ונמדד מול הקובץ בפועל — אותו
פרופיל נשמע אותו דבר בין אם הקובץ הגיע חזק או חלש.

המוזיקה נכנסת **אחרי** עיבוד הקול: המאסטרינג מודד ומתקן את הדיבור,
ורק אז המוזיקה נכנסת מתחתיו. אילו הסדר היה הפוך, המאסטרינג היה
מנרמל את התערובת והקול עצמו לא היה מגיע ליעד.

**העוצמה משתנה לפי הסיפור** (§19): פתיח בינוני, גוף הסיפור נמוך,
שיא רגשי עולה, טענה מרכזית וקריאה לפעולה יורדות כדי שהמילים
יישמעו, והסיום נסגר בפייד ולא נחתך.

### אודיו

מדידה → החלטה → ביצוע → **מדידה חוזרת**. אם התוצאה לא עומדת ביעד,
הקליפ מסומן `דורש בדיקה` והאודיו המקורי נשמר.

| מקור | מה מופעל |
|---|---|
| כבר ב‑‎-14 LUFS, נקי | **כלום** |
| שקט (‎-32 LUFS) | נרמול בלבד |
| רעש רקע מורגש (SNR נמוך) | הפחתת רעש בגודל שנמדד |
| רעידות מתחת ל‑100Hz | סינון תדר נמוך |
| חתוך בהקלטה | אזהרה מפורשת — עיוות כזה אינו ניתן לביטול |

רצפת הרעש נמדדת **רק בהפסקות**. בלי הפסקות אין מדידה, ולכן לא
מופעלת הפחתת רעש — ניחוש היה מרכך קול תקין.

### בדיקת איכות אחרי הרינדור

`exit code 0` של FFmpeg אינו הוכחה. אחרי כל ייצוא נבדקים: אורך מול
התכנית, קיום זרמי וידאו ואודיו, פריימים שחורים (`blackdetect`),
קטעים קפואים (`freezedetect`), דגימת פריימים אמיתית, גבולות
הכתוביות והאזור הבטוח. ממצא ברמת שגיאה מסמן את הקליפ `דורש בדיקה`
— הקובץ קיים וניתן לניגון, אבל אינו מוצג כתקין.

## AI Images — יצירת תמונות

אזור **AI Images** מייצר תמונות מפרומפט, שומר אותן בפרויקט, ומאפשר
לשבץ אותן בקליפ המיוצא.

### הזרימה

```
Prompt  →  השרת  →  ספק התמונות  →  שמירה בפרויקט  →  שיבוץ בקליפ  →  ייצוא
```

### איפה המפתח נמצא — ואיפה לא

כל קריאה לשירות יצירת התמונות יוצאת **מהשרת המקומי בלבד**. המפתח:

- נשמר מוצפן (Fernet) בקובץ `secrets.enc`, עם מפתח מאסטר ב‑`.master.key`
  בהרשאות `0600`;
- ניתן להזנה גם כמשתנה סביבה: `POLIXOR_OPENAI_API_KEY`;
- **אינו** נכלל בקוד הממשק, **אינו** נשמר ב‑`localStorage`, ו‑API
  מחזיר עליו רק מסכה (`sk-●●●●●●abcd`).

### שבע דרכים לשלב תמונה

| תפקיד | מה קורה | משנה את האורך? |
|---|---|---|
| **פתיח** | קטע וידאו מהתמונה בתחילת הקליפ | כן |
| **סיום** | קטע וידאו מהתמונה בסוף | כן |
| **הכנסה מלאה** | נחתכת לתוך ציר הזמן בנקודה שנבחרה | כן |
| **בי‑רול** | מכסה את הפריים, האודיו ממשיך מתחת | לא |
| **שכבה** | פינה קטנה מעל הווידאו, עם שקיפות | לא |
| **רקע** | מאחורי הווידאו לכל אורך הקליפ | לא |
| **תמונת שער** | נשמרת כקובץ, לא נכנסת לווידאו | לא |

הזמן נמדד על **ציר הזמן הערוך** — מה שרואים בנגן — ולא על זמני המקור,
כדי ששיבוץ שנבחר מול הנגן יישאר במקום גם אחרי שהעריכה הסירה אוויר מת.

### Suggest Visuals

כשיש תמלול לקליפ, כפתור **הצע ויזואלים** סורק אותו ומחפש משפטים
שתמונה תחזק — תיאור מקום, תפנית רגשית, קפיצה בזמן, אובייקט מוחשי.

```
00:03–00:07 · רגע רגשי נמוך
„ואז הגעתי למקום הכי נמוך בחיים שלי"
→ a lonely empty road at night, a single figure far away,
  dark moody cinematic, lonely, muted colors, vertical 9:16 composition
```

המשפט מוצג בעברית כדי שתבין למה ההצעה שם; הפרומפט נבנה באנגלית כי
מודלי תמונה מבינים אותה טוב יותר, וניתן לעריכה לפני היצירה.

**אין הוספה אוטומטית.** „צור" ו„שבץ" הן שתי פעולות נפרדות שהמשתמש
לוחץ עליהן. המנוע ההיוריסטי זמין תמיד; אם מוגדר מודל שפה הוא משמש
לתיאורים מדויקים יותר, ונופל חזרה להיוריסטי אם אינו זמין.

### בידוד מהעורך

שילוב התמונות הוא מעבר **נפרד, אחרי** הרינדור הרגיל. אם הוא נכשל,
הקליפ שכבר נוצר נשאר שלם והסיבה נרשמת ב‑`render_params.images_error`.
שיבוץ שקובץ התמונה שלו נמחק מדולג בשקט במקום להפיל את הייצוא.

### הגדרות

| הגדרה | ברירת מחדל | משמעות |
|---|---|---|
| `image_provider` | `openai` | `openai` או `placeholder` (כרטיס מקומי, **לא AI**) |
| `image_model` | `gpt-image-1` | גם `dall-e-3`, `dall-e-2` |
| `image_quality` | `medium` | `low` / `medium` / `high` |
| `image_timeout_seconds` | `120` | פסק זמן לבקשה |
| `image_retries` | `2` | ניסיונות חוזרים — **רק** על תקלה זמנית |

ניסיון חוזר מתבצע על חריגת מכסה, פסק זמן ושירות שאינו זמין, עם השהיה
עולה עד 20 שניות. מפתח חסר, פרומפט פסול, דחיית מדיניות וביטול נכשלים
מיד — ניסיון נוסף רק יבזבז זמן.

> **ספק ה‑placeholder אינו AI.** הוא מצייר כרטיס גרפי במחשב שלך, והוא
> מסומן `is_ai=false` ו„כרטיס מקומי (לא AI)" בכל מקום בממשק ובמסד
> הנתונים. הוא קיים כדי שניתן יהיה לבדוק את שרשרת ההכנסה לווידאו ללא
> מפתח API — לא כדי להתחזות ליצירת AI.

## קליטת שידור חי

שידור חי הוא **עוד מקור**, לא עורך נפרד. אחרי העצירה החומר עובר את
אותו פייפליין בדיוק: תמלול → ניתוח → תכנית עריכה → כתוביות → ייצוא.

```
Paste Live URL  →  Detect  →  Capture  →  Stop  →  Source  →  AI Edit
```

### שיטת ההקלטה

yt-dlp משמש לפענוח הקישור בלבד ומחזיר כתובת מניפסט (HLS/DASH). את
ההקלטה עצמה מבצע FFmpeg ישירות מהמניפסט, **במקטעים סגורים**:

```
ffmpeg -i <manifest> -c copy -f mpegts -t <SEGMENT> seg_000.ts
```

הבחירה במקטעים היא מה שמונע אובדן חומר: כל מקטע שנסגר נרשם מיד ב‑DB,
כך שנפילה של הזרם, של הרשת או של התהליך משאירה בידינו את כל מה שכבר
הוקלט. MP4 כותב את הכותרת בסוף ולכן אינו מתאים כאן; mpegts עמיד
לקטיעה וניתן לאיחוד בהעתקה ללא קידוד מחדש.

כתובות מניפסט פגות תוקף, ולכן הכתובת נפתרת מחדש לפני כל מקטע — וזה
גם מנגנון החיבור מחדש.

### מכונת המצבים

```
idle → detecting → connecting → live ⇄ reconnecting → stopping → completed
                                  ↘ failed
```

מעבר שאינו ברשימת המעברים החוקיים נדחה ונרשם. המצב משתנה ל‑`live` רק
כשבאמת מגיעים בתים מהזרם — לא ברגע שתהליך ההקלטה עלה — כדי שהממשק לא
יציג „משדר" בזמן שהזרם נפול.

### עצירה אינה ביטול

**עצור הקלטה** סוגר את המקטע הנוכחי (שליחת `q` ל‑FFmpeg, לא הרג),
מאחד את כל המקטעים לקובץ אחד, והמשימה ממשיכה לתמלול ולעריכה. ביטול
משימה הוא פעולה אחרת — וגם הוא שומר את מה שכבר הוקלט.

### הגדרות

| הגדרה | ברירת מחדל | משמעות |
|---|---|---|
| `live_segment_seconds` | `300` | אורך מקטע הקלטה |
| `live_max_minutes` | `0` | 0 = עד שתעצור ידנית או שהשידור יסתיים |
| `live_keep_segments` | `false` | לשמור את המקטעים אחרי האיחוד |

| הקשר לפני/אחרי | 2.0 / 1.5 שנ' | שניות שנשמרות סביב רגע השיא |

### קליפים

| הגדרה | ברירת מחדל |
|---|---|
| קליפים ארוכים | 3 קליפים, 2–15 דקות, קטע רציף |
| שורטים | 5 קליפים, 15–60 שניות, מעקב אחרי פנים |
| מספר מרבי למשימה | 12 |
| רזולוציה | 1920×1080 / 1080×1920 |

**הגנה מפני מתיחה:** אם השידור ב‑720p, שורט ייוצא ב‑720×1280 ולא
ב‑1080×1920 מנופח. יש לזה בדיקה: `test_target_resolution_never_upscales`.

### ייצוא

| איכות | CRF | Preset |
|---|---|---|
| גבוהה | 18 | medium |
| בינונית | 21 | faster |
| נמוכה ומהירה | 25 | veryfast |

**האצת חומרה:** `nvenc` (NVIDIA), `qsv` (Intel), `videotoolbox` (Apple).
המערכת בודקת שהמקודד קיים ב‑FFmpeg לפני השימוש, ואחרת חוזרת ל‑libx264.

## מנוע ה‑AI

שלושה מצבים, ניתנים להחלפה במסך ההגדרות:

### 1. מקומי היוריסטי (ברירת מחדל)

ללא מודל שפה כלל. הכותרות והתיאורים נגזרים מהתמלול ומהאותות באמצעות
לקסיקון של כ‑90 ביטויים בעברית ובאנגלית, מסווגי קטגוריה, וניתוח האותות.

- עובד תמיד, ללא רשת וללא עלות
- אין דרישות חומרה נוספות
- **הניסוח פחות מלוטש**, וההבנה של הקשר סיפורי ארוך מוגבלת

### 2. Ollama מקומי

מודל שפה שרץ על המחשב שלך דרך [Ollama](https://ollama.com).

```powershell
ollama pull llama3.1
ollama serve
```

ואז בהגדרות: מצב = `Ollama מקומי`, שם מודל = `llama3.1`.

- ללא עלות, ללא שליחת מידע החוצה
- **דורש חומרה**: 8GB RAM למודל 8B, GPU משפר מאוד את המהירות
- איכות תלויה בגודל המודל

### 3. מודל בענן

Anthropic או OpenAI, עם מפתח API.

- האיכות הגבוהה ביותר לכותרות ולהבנת הקשר
- **נשלחים קטעי תמלול לשירות חיצוני**
- המפתח נשמר **מוצפן** (Fernet) בקובץ מקומי עם הרשאות מוגבלות,
  ולעולם אינו מוחזר לדפדפן — הממשק מציג רק מסכה כמו `sk-●●●●●●abcd`

### מה המודל עושה בפועל

1. **שיפור כותרות ותיאורים** לקטעים שנבחרו
2. **גילוי רגעים שקטים** — קורא את התמלול בחלונות של 8 דקות ומחפש
   רגעים מעניינים שאותות האודיו מפספסים

המודל מתבקש במפורש להסתמך רק על מה שנאמר בפועל, לא להמציא כותרות
מטעות, ולא להבטיח צפיות או ביצועים. **כישלון בשכבה הזו לעולם אינו
מפיל את המשימה** — חוזרים להיוריסטיקה ומדווחים למשתמש.

## ביצועים ומשאבים

### ניהול זיכרון

התוכנה מתוכננת לשידורים של כמה שעות ואינה טוענת וידאו לזיכרון:

| רכיב | איך |
|---|---|
| ניתוח אודיו | קריאה בבלוקים של 30 שניות; הזיכרון תלוי בגודל הבלוק בלבד |
| ניתוח חזותי | פריימים נשאבים דרך צינור FFmpeg ברזולוציה 320px ומעובדים אחד‑אחד |
| חיתוך | `-ss` לפני `-i` — FFmpeg לא מפענח את כל השידור כדי להגיע לדקה 90 |
| Highlights | כל מקטע מקודד בנפרד ואז מחובר עם `concat` demuxer, בלי פענוח חוזר |

### הערכות זמן

**Polixor מציג הערכת זמן רק כשיש מדידות אמיתיות להתבסס עליהן.**

כל שלב שמסתיים רושם לטבלה `stage_timings` את הזמן שלקח ואת אורך
החומר שעובד. ההערכה מחושבת כ‑`יחס_היסטורי × אורך_המדיה`, ומוצגת רק
אם יש כיסוי של לפחות 40% מהשלבים. עד אז מוצג במפורש:

> *"אין עדיין מספיק מדידות כדי להעריך זמן סיום."*

אפשר לראות את היחסים שנצברו ב**הגדרות → מערכת ואחסון → מדידות זמן**.

### GPU

| שימוש | מה נדרש |
|---|---|
| תמלול (CUDA) | NVIDIA + cuDNN 9 + cuBLAS. בהגדרות: מכשיר = `GPU (CUDA)` |
| קידוד (NVENC) | דרייבר NVIDIA עדכני. בהגדרות: האצת חומרה = `NVIDIA NVENC` |

מסך ההגדרות מציג אם GPU ו‑NVENC זוהו במערכת.

### Golden Video — בדיקה ברמת הפריים

`golden_video.py` מייצר וידאו שבו **הזמן מקודד בתוך התמונה** (ערוץ
האדום עולה ליניארית), עם הבזק לבן **וצפצוף 1kHz באותו רגע** בארבע
נקודות ידועות. הפייפליין רץ עליו במלואו, ואז נמדד מה באמת יצא:

| מה נבדק | מה נמדד בפועל |
|---|---|
| כל סימון נוחת במקום שהתכנית חוזה | סטייה מרבית **20ms** (חצי פריים) |
| סנכרון תמונה/קול אחרי החיתוכים | **0ms** |
| אורך הפלט מול סכום הביטים | 28.52 שנ' מול 28.48 |
| מספר ההבזקים = סימונים ששרדו את החיתוך | 4 מתוך 4 |
| שלושה ייצואים רצופים | אותם תזמוני כתוביות, ללא Drift |
| עוצמה סופית | ‎-21.98 ← ‎-14.11 LUFS (יעד ‎-14) |

הבדיקה הזו מצאה ארבעה באגים אמיתיים: כתוביות בקנה מידה שגוי,
סיווג סמנטי שהיה תלוי בזמן המוחלט, גיזום פתיחה שמחק קליפים שלמים,
והגבר אודיו שחושב לפני שלבים שכבר שינו את העוצמה.

`live_hls_lab.py` מקים שידור HLS אמיתי מקומית (FFmpeg מפרסם, שרת HTTP
מגיש), מקליט ממנו במנוע האמיתי, **מפיל את השידור באמצע** ומחזיר אותו
לאוויר, ומאמת שלא אבד חומר. זהו שידור חי אמיתי מעל HTTP — אך **לא**
YouTube או Twitch.

`e2e_images_in_render.py` יוצר תמונה, משבץ אותה כפתיח והכנסה, מייצא
מחדש, **מחלץ פריימים מהקובץ המוגמר** ומשווה אותם לקובץ התמונה. הבדיקה
אינה מסתמכת על הודעת הצלחה: אם התמונה לא באמת בווידאו, היא נכשלת.

## מגבלות ידועות

### שידור חי

- **ההקלטה מתחילה ברגע שאתה לוחץ „התחל הקלטה"** — מה ששודר לפני כן
  אינו נכלל. פלטפורמות מגישות שידור חי בהשהיה של עשרות שניות עד כמה
  דקות, וזו ההשהיה שתראה גם כאן.
- הזרם נשמר במקטעים של 5 דקות (ניתן לשינוי). **נפילה של הזרם אינה
  מוחקת את מה שכבר הוקלט** — כל מקטע שנסגר נרשם מיד.
- אחרי חיבור מחדש יש **תפר**: השניות שבהן הזרם היה נפול אינן מוקלטות.
  מספר החיבורים מחדש ומשך ההקלטה מוצגים בלוח השידור.
- אם מקטע נקטע באמצע, הוא נשמר כפי שהוא ונכנס לאיחוד.
- הקלטה ארוכה תופסת מקום: כ‑45MB לדקה ב‑1080p. אפשר להגביל זמן
  בהגדרות → שידור חי.
- **הקלטה חוקית בלבד.** Polixor אינו עוקף הגבלות גישה, DRM או הרשאות.
  אם הפלטפורמה אינה מאפשרת גישה לזרם, ההקלטה נכשלת עם שגיאה מפורשת.

### יצירת תמונות

- **דורש מפתח API של OpenAI**, שמוזן בהגדרות ונשמר מוצפן מקומית.
  בלי מפתח האזור מוצג כחסום עם הסיבה — לא ככפתור שנראה פעיל.
- שיבוץ תמונות נכנס לווידאו רק ב**ייצוא מחדש** של הקליפ.
- הייצוא נבנה תמיד מחדש מקובץ המקור, ולכן שיבוצים אינם מצטברים בין
  ייצואים חוזרים.
- ספק ה‑`placeholder` יוצר כרטיס גרפי מקומי ו**אינו AI**. הוא מסומן
  ככזה בכל מקום, וקיים רק כדי לאפשר בדיקה ללא מפתח.

### Google Drive

נתמך רק קובץ ששותף עם `כל מי שיש לו הקישור` והרשאת הורדה.
**חיבור חשבון דרך OAuth לא מומש** — קובץ פרטי יחזיר שגיאת הרשאה ברורה.

### Kick

תמיכת yt-dlp ב‑Kick משתנה עם שינויים באתר. אם ההורדה נכשלת, אפשר
להוריד ידנית ולהעלות את הקובץ לתוכנה.

### ציון העניין

הציון הוא **הערכה פנימית בלבד** בסולם 0–100, שנועדה לדרג קטעים זה מול
זה בתוך אותו שידור. **הוא אינו חיזוי של צפיות, CTR או ביצועים**, ולא
כדאי להשוות ציונים בין שידורים שונים.

### זיהוי צחוק

ערוץ ה"צחוק" הוא **היוריסטיקה**, לא מסווג מאומן: הוא מחפש אנרגיה גבוהה
יחד עם מודולציית עוצמה מהירה (4–8 הרץ) ומרכז ספקטרלי גבוה. מוזיקה
קצבית או רעש רקע עלולים להפעיל אותו. הוא אות תומך, לא הכרעה.

### מעברים בין מקטעים

בסרטון Highlights המעברים הם fade קצר (0.25 שנ') בקצוות כל מקטע,
ואז חיבור בלי קידוד חוזר. **אין מעברי xfade** — הם היו מחייבים פענוח
וקידוד מחדש של כל הסרטון.

## פתרון תקלות

### "FFmpeg לא נמצא"

```powershell
winget install Gyan.FFmpeg
# סגור ופתח PowerShell מחדש, ואז:
ffmpeg -version
```

אם עדיין לא נמצא, הגדר נתיב מפורש ב‑`.env`:
```
POLIXOR_FFMPEG=C:\ffmpeg\bin\ffmpeg.exe
POLIXOR_FFPROBE=C:\ffmpeg\bin\ffprobe.exe
```

### כתוביות בעברית מוצגות כריבועים

הגופן שנבחר לא תומך בעברית. בהגדרות → כתוביות, בחר `Arial`,
`Segoe UI` או `Noto Sans Hebrew`. Polixor מנסה לבחור חלופה
אוטומטית, אבל אפשר לכפות ידנית.

### כתוביות בעברית מוצגות הפוך

ה‑FFmpeg שלך לא כולל `fribidi`:
```powershell
ffmpeg -version | findstr fribidi
```
אם אין פלט — התקן בילד מלא (Gyan full) במקום `essentials`.

### "לא ניתן להוריד את מודל התמלול"

נדרשת גישה לאינטרנט בהורדה הראשונה. אם יש חומת אש:
1. הורד את המודל במחשב אחר
2. העתק את תיקיית המודל ל‑`%LOCALAPPDATA%\Polixor\models`
3. או הגדר `transcript_provider = none` — המערכת תעבוד לפי אודיו
   ווידאו בלבד, ללא כתוביות

### "לא נמצאו רגעים מתאימים"

- העלה את **רמת הרגישות** בהגדרות
- הרחב את טווח אורך הקליפ
- ודא שיש אודיו בשידור
- שידור קצר מ‑5 שניות לא ינותח

### ההורדה מ‑YouTube נכשלת

```powershell
.\.venv\Scripts\pip install -U yt-dlp
```
YouTube משנה את המבנה שלו תכופות; yt-dlp מתעדכן בתדירות גבוהה.

### העיבוד איטי מאוד

| פעולה | שיפור צפוי |
|---|---|
| מודל תמלול `small` במקום `large-v3` | פי 4–6 |
| איכות ייצוא `בינונית` | ~30% |
| דגימת פריימים 0.5/שנ' | ~40% מזמן הניתוח |
| האצת חומרה NVENC | פי 3–5 בייצוא |
| תמלול על GPU | פי 5–10 |

### "אין מספיק מקום בדיסק"

הגדרות → מערכת ואחסון → **נקה קובצי עבודה זמניים**.
מוחק אודיו מחולץ, תמלול ונתוני ניתוח של משימות שהסתיימו;
קובצי המקור והקליפים נשמרים.

### הממשק לא נטען

```powershell
cd frontend
npm install
npm run build
```
בלי זה השרת פועל עם API בלבד: <http://127.0.0.1:8756/docs>

## מדיניות תוכן וזכויות

Polixor נבנה במפורש **בלי** מנגנוני עקיפה:

- ❌ אין עקיפת DRM. תוכן מוגן מזוהה ונדחה עם הודעה ברורה.
- ❌ אין עקיפת הגבלות גיל, אזור גאוגרפי או תוכן בתשלום.
- ❌ אין גישה לדפדפן שלך ואין שליפת עוגיות ממנו.
- ✅ ניתן לספק **בעצמך** קובץ `cookies.txt` שייצאת, כדי להוריד תוכן
  שהחשבון שלך מורשה לצפות בו.
- ✅ כל הנתונים נשמרים מקומית כברירת מחדל.
- ✅ מפתחות API מוצפנים בדיסק ואינם נחשפים בדפדפן.

**האחריות על השימוש בתוכן היא שלך.** ודא שיש לך זכות להוריד, לערוך
ולפרסם את החומר, ושהשימוש עומד בתנאי השימוש של הפלטפורמה ובדיני
זכויות היוצרים החלים עליך.

Polixor **אינו יוצר כותרות מטעות ואינו ממציא כתוביות** — כל טקסט
שמוצג מקורו בתמלול של מה שנאמר בפועל, וניתן לתקן אותו לפני הפרסום.
